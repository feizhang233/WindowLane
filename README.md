# WindowLane

原生 macOS 視窗工作區工具。最多加入六個已開啟的視窗，讓目前視窗位於中央，以兩側預覽與底部切換條切換工作。第一版以單一螢幕為單位，介面採繁體中文。

0.2.1 預設採直接切換：啟動時先將所有受管理視窗解除最小化、排列在同一個主要區域，維持開啟並前後堆疊。正常切換只將目標原生視窗帶到前方並交接輸入焦點，不反覆收起、縮放或等待預覽擷取。暫時放大與恢復時會一次調整整組視窗，後續切換仍沿用已準備的尺寸。

介面採中性的液態玻璃：透明管理視窗、未染色的玻璃卡片與一般按鈕、浮動切換條，以及預覽上的玻璃控制元件。已移除固定藍色填色；啟動／完成保留適應明暗模式的中性強調樣式，選取以邊框、字重和淡灰底表示。系統焦點框與原生控制項仍跟隨 Mac 的強調色。這些選擇依循 Apple 的[色彩規範](https://developer.apple.com/design/human-interface-guidelines/color)與[按鈕規範](https://developer.apple.com/design/human-interface-guidelines/buttons)。macOS 26 以上使用[系統原生 Liquid Glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)，macOS 14–25 使用半透明材質替代。外觀跟隨系統明暗模式；降低透明度或提高對比時改用實色表面。文件預覽仍按原尺寸裁切，保持文字清晰。

整體背景預設為半透明毛玻璃（35% 透明度）。右上角「設定」或 Command + , 開啟獨立設定視窗，分為「外觀、切換、權限」。外觀中的「應用與工作區透明度」和「設定視窗透明度」各自保存，可調至 0–80%；另可選擇本機壁紙、調整模糊（0–60 pt）及恢復預設。壁紙等比例填滿背景，過長部分會裁切；文字、控制項與文件預覽不受背景透明度影響。

背景設定在重新開啟後保留。壁紙會轉成最長邊不超過 4096 像素的本機副本，存於 `~/Library/Application Support/WindowLane/wallpaper.png`，原圖保持完整。移動原圖不影響背景；「移除壁紙」只移除這份副本。圖片讀取失敗會保留原背景，已存副本遺失或損壞則回到毛玻璃並提示重新選圖。沒有上傳或遠端儲存。

## 執行

直接開啟 `dist/WindowLane.app` 即可使用，已編譯版本適用於 Apple Silicon Mac、macOS 14 或以上。

0.2.1 直接切換版正在進行最終驗證與封裝；預定封裝為 `dist/WindowLane-0.2.1-arm64.zip`。完成後，[建置清單](verification/build-manifest.json) 會記錄版本、程式與封裝檔的 SHA-256，以及對應報告。最新進度見[測試紀錄](verification/TESTING.md)最上方；歷史 [0.2.0 封裝](dist/WindowLane-0.2.0-arm64.zip)的結果另行保留。

只有自行修改與編譯原始碼時才需要 Xcode／Command Line Tools：

```sh
cd WindowLane
./scripts/build-app.sh
open dist/WindowLane.app
```

建置產物使用本機臨時簽署，可在這台 Mac 上執行；尚未提供 Developer ID 簽署、公證或安裝程式。請從固定位置啟動 `.app`，避免搬動或重新簽署後影響 macOS 權限識別。

## 操作

1. 開啟 WindowLane，依介面提示啟用所需權限。也可以先使用內建測試視窗體驗。
2. 從視窗清單加入需要的視窗；同一應用的不同視窗會分別列出。
3. 啟動工作區後，使用左右預覽、底部位置標記、橫向滾輪或快捷鍵切換。
4. 在管理介面重新排序或移除視窗。「移除」不會關閉視窗或文件。
5. 退出工作區時，工具先取消尚未完成的切換，再恢復啟動前的位置、大小與最小化狀態。復原期間不能啟動新工作區；結束 WindowLane 也會先等待復原完成。

| 操作 | 快捷鍵 |
| --- | --- |
| 前一個／後一個視窗 | Control + Option + ←／→ |
| 直接前往第 1～6 個視窗 | Control + Option + 1～6 |
| 暫時放大／恢復預覽 | Control + Option + Return |
| 退出並恢復原位置 | Control + Option + Esc |
| 加入目前視窗 | Control + Option + A |
| 顯示管理介面 | Control + Option + Space |
| 設定 | Command + ,（WindowLane 在前景時） |

切換在兩端停止，不循環跳轉。橫向滾輪預設可在目前取得焦點的受管理視窗、兩側預覽及切換條使用；同一應用的其他視窗與附屬對話框不應觸發全局切換。預設累積閾值為 80，可在設定改為 30–180，越高越不容易誤觸。每次有相位的手勢最多切換一個視窗，忽略慣性、垂直輸入及忙碌期間的操作；普通滑鼠滾輪採累積與冷卻。可關閉此功能，或改成「僅切換條」。外部應用仍會收到自己的橫向捲動事件，閱讀寬表格或移動畫布時可使用僅切換條模式。實作依循 Apple 的[NSEvent 監看規則](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents(matching:handler:))，不攔截其他應用的事件。

## 系統權限與實際行為

- **輔助使用**：讀取並調整其他應用視窗的位置、大小、最小化狀態，以及切換焦點。權限由使用者在「系統設定 → 隱私權與安全性 → 輔助使用」授予；本機 macOS 27 顯示為「Device Control and Data Access」。
- **螢幕錄製**：取得視窗內容預覽；名稱可能依 macOS 版本顯示為「螢幕與系統音訊錄製」。視窗快照用於記憶體內顯示，不會由本工具另存到磁碟。

已允許的權限狀態收納在「設定 → 權限」，主畫面只顯示尚未完成的授權提示；權限被撤銷時會重新顯示。

本工具透過 macOS 公開 API 管理外部視窗。中央是原應用的可操作視窗；兩側是切換預覽，沒有把外部應用嵌入本工具。預覽是最近一次擷取的快照，並非可以直接操作或持續更新的即時視窗。0.2.1 的非作用中視窗保持開啟，疊在目前視窗後方；切換完成後另行更新預覽，不阻擋焦點交接。原應用的透明區域可能透出後方視窗。退出時仍嘗試恢復每個視窗的原位置、大小與原最小化狀態；文件、游標與未送出的文字由原應用保存。

其他應用可能限制視窗的最小尺寸、拒絕移動／調整大小，或無法取得預覽。全螢幕視窗、其他 Space 的視窗、受保護內容及系統視窗不保證支援。視窗已關閉、應用已結束，或螢幕已拔除時，原來的位置也可能無法完整還原；無法確認復原的視窗會保留記錄，並在管理畫面提供失敗資訊與「重試復原」。

## 第一版範圍

單工作區、最多六個視窗、中央操作區、相鄰預覽、快捷鍵與可調閾值的橫向滾輪、排序、暫時放大及位置恢復。雙視窗固定對照、多工作區分組、重新打開文件內容和跨 Space 工作流程留待後續版本。

## 結構

- `WindowLaneCore`：與介面分離的順序模型、版面配置、原始視窗位置紀錄及座標轉換。
- `WindowLane`：AppKit／SwiftUI 介面、視窗控制、全域快捷鍵、預覽與測試視窗。
- `Tests/WindowLaneCoreTests`：容量與識別一致性、排序、移除、端點切換、負座標外接螢幕、AX 座標往返及恢復資料測試。

版面使用螢幕的 `visibleFrame` 保留選單列與 Dock 空間。Accessibility 的左上角座標與 AppKit 的左下角座標，統一以主螢幕完整高度轉換，避免外接螢幕在負座標時上下顛倒。

## 調試

```sh
swift test
swift build
```

建議依序檢查：

1. 用內建測試視窗確認文字輸入、文字選取、切換、排序與退出後恢復。
2. 授予權限後，用兩個測試文件與一個瀏覽器視窗確認跨應用操作。
3. 在第六個視窗加入後確認第七個被拒絕；移除其中一個不應關閉其文件。
4. 拔除外接螢幕、關閉一個受管理視窗，以及拒絕權限，確認工具顯示可處理的狀態。
5. 快捷鍵無效時，檢查介面的註冊失敗提示和其他視窗管理工具的按鍵衝突。

若 macOS 已開啟權限但仍無效，請退出工具，再由相同位置重新啟動；重新建置本機簽署版本後，可能需要從權限清單移除舊項目，再用「＋」選取目前的 `.app`。本機測試確認，僅切換開關未必會更新舊簽署記錄。

復原記錄位於 `~/Library/Application Support/WindowLane/recovery.json`。發生權限變更或無法確認的視窗錯誤時會保留記錄。重試會核對原應用的程序、身分與啟動資料，並尋找原視窗；暫時讀不到視窗清單、位置或身分，不會當作已關閉而清除記錄。若應用仍在執行，已關閉的視窗也可能留待手動處理；確認已手動恢復後，可在介面按「已手動復原」清除待辦記錄。自動測試使用各次執行專用的臨時復原檔，不會讀取或覆寫使用者這份記錄。

0.2 起的取消與復原處理保留於 0.2.1：退出先停止舊操作，再用獨立任務復原；復原期間阻止新工作區啟動。結束程式等待復原任務完成，失敗保留記錄。0.2.1 的直接切換使用短暫、無動畫的輸入遮罩，再提升目標原生視窗並確認焦點。影像擷取同時最多一個底層任務，取消／逾時／過期結果不再回寫；啟動前最後一次讀取原始位置，避免長時間擷取期間的舊位置覆寫。原應用的身分與啟動資料在加入時固定，避免 PID 重用；第二個一般實例會返回既有程式，避免競爭管理同一組視窗。設定視窗可獨立調整透明度，已授權項目收納於「設定 → 權限」。這些修正不代表所有應用、休眠或崩潰情境都已完整驗證。

**0.2.1 的最終測試數量、切換延遲與封裝結果待本輪驗證完成後記錄。** 回歸會核對所有視窗的共同尺寸、正常／放大模式切換沒有重複幾何或最小化寫入，以及退出後原位置與原最小化狀態保持。啟動、放大／還原與退出仍涉及布局處理，其耗時與正常切換分開記錄。
