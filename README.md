# WindowLane

原生 macOS 視窗工作區工具。最多加入六個已開啟的視窗，以單頁或兩窗並排方式工作，透過橫向滾輪、兩側預覽與底部切換條導覽。可為目前排版命名並保留，之後直接選擇。一次管理一個螢幕上的一組視窗，介面採繁體中文。

逐頁切換與快捷鍵保留平滑翻頁效果：單頁啟動時先將所有受管理視窗解除最小化、排列在同一個主要區域，維持開啟並前後堆疊。切換取得目標的真正焦點後，以目前頁面的新快照向左或向右滑出，配合輕微傾斜，露出可操作的下一個視窗；效果約 280 ms。一般單頁切換不反覆收起、移動或縮放。進出並排及暫時放大時會調整整組視窗，原始位置仍保留供退出復原。

逐頁效果只使用記憶體內的新快照。外部視窗擷取的等待預算為 100 ms；沒有影像、擷取太慢或正忙碌、影像尺寸不符，以及系統開啟「減少動態效果」時，會直接切換。呈現期間暫停重複切換並擋住畫面上的滑鼠／捲動操作，鍵盤焦點留在已切換到的應用；退出工作區會立即移除過渡畫面，再復原原始視窗。

橫向滾輪預設使用「連續翻頁」：側滑距離直接決定翻開的比例，停止後保留該比例，不自動吸附到最近的一整頁。尺寸限制允許時，翻開一半會讓兩個真實視窗各佔一半；也可以留下不同比例。滾動期間的過渡使用記憶體快照，停止後移除快照並排列可操作的原生視窗，文件與輸入仍由原應用處理。預覽中點擊、開始拖曳或切換至另一個應用，會取消這次手勢並回到上次已接受的排版；實際兩窗互動在停止側滑並套用原生排版後進行。兩窗都有最小寬度限制，會依應用實際接受的寬度調整分界，保留所選翻頁比例。接近整頁的極小差值視為整頁；兩個應用無法同時放下或拒絕尺寸時，會提示並回到上次可用排版，工作區保持運行。切換條的「並排」可直接設定兩窗各半。

介面採中性的液態玻璃：透明管理視窗、未染色的玻璃卡片與一般按鈕、浮動切換條，以及預覽上的玻璃控制元件。已移除固定藍色填色；啟動／完成保留適應明暗模式的中性強調樣式，選取以邊框、字重和淡灰底表示。系統焦點框與原生控制項仍跟隨 Mac 的強調色。這些選擇依循 Apple 的[色彩規範](https://developer.apple.com/design/human-interface-guidelines/color)與[按鈕規範](https://developer.apple.com/design/human-interface-guidelines/buttons)。macOS 26 以上使用[系統原生 Liquid Glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)，macOS 14–25 使用半透明材質替代。外觀跟隨系統明暗模式；降低透明度或提高對比時改用實色表面。文件預覽仍按原尺寸裁切，保持文字清晰。

整體背景預設為半透明毛玻璃（35% 透明度）。右上角「設定」或 Command + , 開啟獨立設定視窗，分為「外觀、工作區、切換、權限」。外觀中的「應用與設定視窗透明度」同時套用於主視窗與設定視窗；「工作區透明度」單獨控制工作區背景，兩者各自保存，可調至 0–80%；另可選擇本機壁紙、調整模糊（0–60 pt）及恢復預設。壁紙等比例填滿背景，過長部分會裁切；文字、控制項與文件預覽不受背景透明度影響。

原主畫面的範圍控制已收納至「設定 → 工作區」：在尚未啟動時調整「主視窗寬度」（80–90%，預設 84%）與「螢幕」，重新開啟後保留。這是工作區及預覽的排列範圍，並非另存截圖的裁切工具；正常預覽仍只留在記憶體中。

背景設定在重新開啟後保留。舊版本升級時，兩組透明度先沿用原本的應用／工作區數值，再分別調整；原有壁紙與模糊設定保留。壁紙會轉成最長邊不超過 4096 像素的本機副本，存於 `~/Library/Application Support/WindowLane/wallpaper.png`，原圖保持完整。移動原圖不影響背景；「移除壁紙」只移除這份副本。圖片讀取失敗會保留原背景，已存副本遺失或損壞則回到毛玻璃並提示重新選圖。沒有上傳或遠端儲存。

## 執行

需要 macOS 14 或以上及 Xcode 26 或以上的工具鏈（含 macOS 26 SDK），才能編譯原生 Liquid Glass 路徑。本機已驗證版本為 **0.2.1 build 8**，測試環境為 Apple Silicon；其他硬體／系統版本的相容性尚未全面驗證。目前沒有公證的公開下載版，請從原始碼建置：

```sh
git clone https://github.com/feizhang233/WindowLane.git WindowLane
cd WindowLane
swift test --disable-sandbox
bash scripts/build-app.sh --disable-sandbox
open dist/WindowLane.app
```

建置腳本預設使用臨時簽署（ad-hoc），不需要開發者憑證。若希望更新後保留固定開發簽署身分，可指定自己鑰匙圈中可用的憑證：

```sh
WINDOWLANE_SIGNING_IDENTITY="Apple Development: Your Name (TEAMID)" \
  bash scripts/build-app.sh --disable-sandbox
```

亦可在不納入 Git 的 `scripts/signing.local.sh` 設定 `WINDOWLANE_SIGNING_IDENTITY`；環境變數可覆寫本機值。此工程的原有本機簽署已保留在該檔。私人金鑰與憑證檔不應提交。Bundle ID 為 `com.feizhang.windowlane`。

產物位於 `dist/WindowLane.app`；此目錄不納入 Git。日常使用建議放在固定位置，例如 `~/Applications/WindowLane.app`。替換執行中的版本前，先退出工作區、等待原視窗復原並結束 WindowLane。Xcode 的 Swift Package Run 是另一份除錯執行檔，可能需要獨立授權。臨時簽署重新建置後可能需要重新授予權限；Developer ID 簽署與公證另行處理。

本機進度與歷史報告見[目前進度](CURRENT_STATE.md)及[驗證紀錄](verification/TESTING.md)。歷史 GUI 通過結果不代表每台 Mac 都已驗證；本次原始碼上傳不包含新的 App 發布封裝。`scripts/package-app.sh` 僅用於已核對來源、二進位和同次測試報告的產物，不應用舊報告直接封裝新版本。

## 操作

1. 開啟 WindowLane，依介面提示啟用所需權限。也可以先使用內建測試視窗體驗。
2. 從視窗清單加入需要的視窗；同一應用的不同視窗會分別列出。
3. 在「設定 → 工作區」選擇螢幕及單頁寬度；在管理介面排序或移除視窗。「移除」不會關閉視窗或文件。
4. 啟動後，使用橫向滾輪連續翻開整頁或一部分；也可使用左右預覽、底部位置標記及快捷鍵逐頁切換。按「並排」可展開兩個真實視窗各半。
5. 按「儲存目前版面…」，輸入名稱，保存目前的視窗順序、翻頁比例、作用中視窗、單頁寬度與螢幕。
6. 後續先開啟原來的應用與文件，在「已儲存工作區」選擇排版，再按「啟動工作區」。
7. 退出時先取消尚未完成的切換與拖曳導覽，再恢復啟動前的位置、大小與最小化狀態。復原期間不能啟動新工作區；結束 WindowLane 也會先等待復原完成。

管理畫面與「設定 → 工作區」共用已儲存排版的選單，最多保存 24 個，每個最多六個視窗。設定頁提供「更新版面」、「重新命名…」、「刪除」及「復原刪除」；刪除排版不會關閉文件。排版只儲存在 `~/Library/Application Support/WindowLane/workspaces.json`，不包含文件內容或預覽影像。相同應用程序的視窗優先以原身分核對；應用重啟後只接受同 Bundle ID、完全相同標題且唯一的已開啟視窗。遺失或辨識不唯一時保留目前選取並提示，不部分套用、不猜測相似標題，也不自動重開應用或文件。原螢幕未連接時會提示改用目前螢幕。資料無法讀取時保留原檔並停止覆寫。

| 操作 | 快捷鍵 |
| --- | --- |
| 前一個／後一個視窗 | Control + Option + ←／→ |
| 直接前往第 1～6 個視窗 | Control + Option + 1～6 |
| 暫時放大／恢復預覽 | Control + Option + Return |
| 退出並恢復原位置 | Control + Option + Esc |
| 加入目前視窗 | Control + Option + A |
| 顯示管理介面 | Control + Option + Space |
| 設定 | Command + ,（WindowLane 在前景時） |

切換在兩端停止，不循環跳轉。在「設定 → 切換」選擇「連續翻頁」或「逐頁切換」，可關閉橫向滾輪功能，或改成「僅切換條」。工作區模式涵蓋取得焦點的具體受管理視窗、兩側預覽及切換條；同應用的其他視窗和附屬對話框不能觸發。兩種模式都忽略垂直與慣性輸入，原生拖曳按住滑鼠時暫停滾輪翻頁。

「翻頁距離」／「切換閾值」可設為 30–180，預設 80。連續模式中數值越高，翻過一頁需要的側滑距離越長；有相位的手勢結束時保留比例，普通滑鼠停止輸入約 160 ms 後套用兩窗或整頁。逐頁模式則累積至閾值才切換，有相位的手勢最多切換一頁，普通滾輪使用冷卻時間。外部應用仍收到自己的橫向捲動事件；閱讀寬表格或移動畫布時，可改用僅切換條模式。實作依循 Apple 的[NSEvent 監看規則](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents(matching:handler:))，不攔截其他應用的事件。

兩窗並排時，直接從來源視窗拖動文件、圖片或文字到另一個真實視窗；操作是否接受取決於來源及目標應用支援的資料類型。單頁時，可拖曳至左／右預覽停留約 0.45 秒，讓相鄰真實視窗展開，再移入該視窗放下。邊緣只協助導覽，不接收資料，也不替代原應用的拖曳工作；停在同一邊緣不會連續自動翻過多頁。

## 系統權限與實際行為

- **輔助使用**：讀取並調整其他應用視窗的位置、大小、最小化狀態，以及切換焦點。權限由使用者在「系統設定 → 隱私權與安全性 → 輔助使用」授予；本機 macOS 27 顯示為「Device Control and Data Access」。
- **螢幕錄製**：取得視窗內容預覽；名稱可能依 macOS 版本顯示為「螢幕與系統音訊錄製」。視窗快照用於記憶體內顯示，不會由本工具另存到磁碟。

已允許的權限狀態收納在「設定 → 權限」，主畫面只顯示尚未完成的授權提示；權限被撤銷時會重新顯示。

本工具透過 macOS 公開 API 管理外部視窗。單頁的中央與半翻開時的兩個操作區，都是原應用的真實視窗；兩側預覽是最近一次擷取的快照，不是嵌入或可直接編輯的即時視窗。逐頁效果使用切換前的新快照；連續翻頁過渡可使用已有快照或名稱卡片，停止後由真實視窗接手。非顯示視窗保持開啟並堆疊於後方，兩個並排視窗會在焦點交接完成後提升到其他受管理視窗前方。原應用的透明區域可能透出後方視窗。退出時仍嘗試恢復每個視窗的原位置、大小與原最小化狀態；文件、游標與未送出的文字由原應用保存。

其他應用可能限制視窗的最小尺寸、拒絕移動／調整大小，或無法取得預覽。全螢幕視窗、其他 Space 的視窗、受保護內容及系統視窗不保證支援。視窗已關閉、應用已結束，或螢幕已拔除時，原來的位置也可能無法完整還原；無法確認復原的視窗會保留記錄，並在管理畫面提供失敗資訊與「重試復原」。

## 目前範圍

一次運行一個工作區、最多六個視窗、可命名保存排版、連續部分翻頁與兩窗原生交互、邊緣拖曳導覽、相鄰預覽、快捷鍵、排序、暫時放大及位置恢復。多個工作區同時運行、自動重開文件與跨 Space 工作流程仍屬後續範圍。支援兩窗排列不代表所有應用都接受相同拖放資料，個別應用與文件類型需另行確認。

## 結構

- `WindowLaneCore`：順序模型、單頁／部分翻頁配置、連續滾輪位置、已儲存排版與保守匹配、原始視窗位置及座標轉換。
- `WindowLane`：AppKit／SwiftUI 介面、視窗控制、全域快捷鍵、預覽與測試視窗；`PageTurnTransition.swift` 負責逐頁呈現，`ContinuousPagePresentation.swift` 負責連續快照過渡，`DragTransferRouter.swift` 負責邊緣拖曳導覽。
- `Tests/WindowLaneCoreTests`：容量與識別一致性、排版保存與錯誤檔保留、部分翻頁、滾輪 gate、排序／移除、負座標、AX 座標往返及復原資料測試。

版面使用螢幕的 `visibleFrame` 保留選單列與 Dock 空間。Accessibility 的左上角座標與 AppKit 的左下角座標，統一以主螢幕完整高度轉換，避免外接螢幕在負座標時上下顛倒。

## 調試

```sh
swift test
swift build
```

建議依序檢查：

1. 用內建測試視窗確認文字輸入、文字選取、切換、排序與退出後恢復。
2. 授予權限後，用兩個測試文件與一個瀏覽器視窗確認跨應用操作。
3. 在第六個視窗加入後確認第七個被拒絕；移除其中一個不應關閉其文件。
4. 拔除外接螢幕、關閉一個受管理視窗，以及拒絕權限，確認工具顯示可處理的狀態。
5. 快捷鍵無效時，檢查介面的註冊失敗提示和其他視窗管理工具的按鍵衝突。

若 macOS 已開啟權限但仍無效，請退出工具，再由相同位置重新啟動。此次從臨時簽署遷移至 Apple Development 時，曾需要從權限清單移除舊 App 項目，再用「＋」選取固定位置的 `.app`；僅切換開關未能更新舊記錄。完成遷移後，同一身分的 build 3 → 4 更新已確認無須再次授權。

復原記錄位於 `~/Library/Application Support/WindowLane/recovery.json`。發生權限變更或無法確認的視窗錯誤時會保留記錄。重試會核對原應用的程序、身分與啟動資料，並尋找原視窗；暫時讀不到視窗清單、位置或身分，不會當作已關閉而清除記錄。若應用仍在執行，已關閉的視窗也可能留待手動處理；確認已手動恢復後，可在介面按「已手動復原」清除待辦記錄。自動測試使用各次執行專用的臨時復原檔，不會讀取或覆寫使用者這份記錄。
