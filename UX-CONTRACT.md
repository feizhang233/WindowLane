Source: user's six-window workspace brief and accepted additions: named layouts, settings-owned area controls, continuous partial paging and interaction between two real windows. `README.md` records public macOS API limits. No server, account, web form or remote storage.

A manager opens or resumes without modifying external windows. Start finishes optional captures, rechecks its operation token, then reads original geometry immediately before journaling and mutation. Single-page Start prepares all managed windows unminimized at the same main frame and keeps them stacked. Starting a saved fractional arrangement instead prepares and raises both original panes above the remaining managed stack. Normal stepped selection from a single page serializes a direct native focus operation, preceded by a short nonanimated input shield. A fresh outgoing-window capture may prepare its overlay; external ScreenCaptureKit capture has a 100 ms wait budget, and missing, slow or already-busy capture falls back to direct focus. An invalid or incompatible logical image size and Reduce Motion also skip presentation. For this stepped effect an older cached preview or an incoming-window image cannot substitute for the fresh outgoing snapshot.

Release the nonanimated input shield before actual focus handoff. Only after native focus succeeds does the selected ID change. If an outgoing overlay was prepared, play its 280 ms directional slide and subtle perspective tilt above the already-focused real destination. Forward leaves left; backward leaves right. The nonactivating overlay cannot become key/main and absorbs pointer/scroll input while visible; keyboard input remains with the destination. Keep the UI busy through presentation completion, then settle the rail and refresh the previous window's edge preview in the background. Edge-preview failure retains the previous image or name card. Normal single-page selection neither re-places the next window nor minimizes/hides the previous one; entering or leaving a fractional layout is a separate geometry operation. Capture wait, native focus and presentation completion are distinct latency measures.

Continuous input preserves a floating-point page position. Reversal subtracts input distance smoothly; endpoints clamp without wrapping. During input, ContinuousPagePresentation uses memory snapshots or name placeholders while the last accepted real geometry stays fixed. Phase end, or 160 ms idle for an unphased wheel, commits the fraction rather than rounding it to the nearest page. BookPageLayout normalizes only values within 0.002 of an integer and enforces minimum native pane widths. Position n + 0.5 exposes two equal adjacent panes when their minimum widths permit it; other fractions expose unequal panes. A commit places both real windows, confirms the selected pane's native focus unless preserving an existing drag focus, then raises the two panes above the managed stack with the focused pane last, and removes the snapshot cover before pointer interaction resumes. Sustained wider-than-requested size readback may establish a per-window minimum width; adapt the real pane boundary while retaining the fractional position. If the two minimum widths cannot fit, or another size/position request is rejected, restore the exact last accepted real frames and active window, remove the overlay and keep the workspace running. Only a failed rollback exits into original-frame recovery. Original recovery values are never replaced by these intermediate layout frames. A saved split that cannot fit starts as a single page with an explanation. Clicking, drag initiation or frontmost-application change cancels an uncommitted preview. Cancel returns to the accepted fraction without changing original recovery values. Editing and drag/drop occur after release and native commit, not in the snapshot layers. Reduce Motion skips moving images, not the selected fractional layout.

The two exposed panes are original native windows. Their own views own edit, scroll and drag/drop behavior. Native drag delivery depends on source/destination support for the advertised type; the workspace does not manufacture a universal file/image transfer capability. A drag dwelling on an available edge preview for 450 ms may reveal the adjacent real pane while keeping the original source session. Move into that pane to drop. An edge never accepts a payload, reads its bytes, resolves a file promise or creates a replacement drag session. The same stationary edge visit navigates once; workspace Stop and drag end cancel hover state. Suspend wheel paging while any mouse button is held. Router state, frame readback and window visibility are distinct from an actual accepted drag payload and need separate evidence.

Expansion and its reversal place all managed windows at the new shared frame, then return focus to the active window. They must not change the saved original frame/minimized state. Stop invalidates tokens and cancels old operations, continuous gestures, drag navigation and previews; synchronously removes all page overlays, releases images and resumes any animation waiter; then waits for pending writes to unwind and independently restores every original frame/minimization. Fractional commits cannot overwrite those originals. Stale completion or cancellation handlers cannot affect a newer overlay. New work remains blocked during restoration. Failures and journal write failures preserve recovery data for retry. App exit waits for Stop; repeated Stop cannot cancel restoration. A corrupt journal blocks Start until explicit acknowledgement. Closed windows are removed only after positive evidence; permission loss is not closure. Automated fixture runs have separate journals, preset archives and area preferences and never consume a user's unresolved records or saved layouts.

Retry does not depend on the narrower eligibility rules used to add new windows. Missing bundle/launch identity, unavailable or empty AX window lists, unreadable frames, ambiguous correspondence, and changing geometry keep the record pending. A confirmed different original process may be discarded; temporary identity/read failures may not. The same-session AX identity is preferred; restart lookup requires the saved WindowServer ID's owner and a unique complete geometry correspondence. A title match alone is never sufficient. After lookup, frame and minimized state must both restore successfully before the record is omitted from the next atomic journal. Failure to write that journal does not clear the in-memory queue.

Original frames can extend beyond a display edge. Temporary placement to permit growth may be used only as a step toward the unchanged saved frame. Final verification still checks the original target; silently accepting a smaller clamped frame is a failure, not completed recovery. The confirmed Safari bottom-edge clamp and the final recovery result are tracked separately in verification/TESTING.md.

Reordering uses stable IDs and keeps the active window selected. Drag and arrow actions are equivalent. Removal is reversible by adding the still-open window, and never closes an external document. The manager has a local bounded six-item lane and a scrolling discovered-window list; query clear is immediate. Native macOS control semantics, focus and shortcut labels are canonical. No modal approval for reversible layout changes. System permission controls remain owned by macOS.

Named layouts persist up to 24 presets of up to six concrete window descriptors, saved order, active slot, display, width and fractional position in an atomic local workspaces.json under Application Support. Names contain 1–80 characters; duplicates and control characters are rejected. Save/update succeed only after the new archive is written; update keeps identity and creation time. Delete removes only the preset and offers undo. Reload failures, corrupt or unsupported-version files and failed writes preserve accepted data and prevent silent replacement. Presets contain no captured pixels or document bytes.

Applying a preset first resolves the whole selection. An unchanged process/window/launch identity can tolerate a title change. Otherwise only an exact Bundle ID and nonempty exact title that identify one current window are accepted; multiple saved slots cannot claim one current window. Missing or ambiguous windows explain what to reopen manually and leave current order, entries, width and page position unchanged. Demonstration identity uses the fixed fixture index, independent of saved order. Applying does not launch apps, open documents or move external windows until Start. A missing saved display uses the current one with an explanation. These preset rules are intentionally distinct from the stricter original-process recovery contract above; they cannot justify clearing uncertain recovery records.

Preview pixels are optional cached snapshots in memory. No live preview claim. A local recovery record under Application Support persists window identifiers, titles and original frames. Background settings persist in local preferences and the selected wallpaper has a managed PNG copy in Application Support; its source is never changed. No network storage or upload. Demonstration mode has a visible label and app-owned editable windows. Its test results cannot establish external-window integration.

Stacked windows remain real application windows. Occlusion is not closure and cannot clear their recovery records. Preview capture continues to target the exact desktop-independent window, including when it is covered by another managed window; a screen-rectangle capture cannot substitute for it. Transparent application content may show the window behind it. A user or target application that independently minimizes or changes a window can require corrective handling; the no-repeat-layout guarantee applies to the prepared single-page stepped-switch path. Start, fractional commits, expansion/reversal and restoration have separate geometry costs and latency evidence.

The standalone settings window shows the current mode, source filename and independently labeled application-and-settings-window and workspace transparency controls. The manager and settings background consume the same application value; the workspace backdrop and its preview consume the workspace value. Older preferences initialize both groups from the previous application/workspace value, preserving the workspace appearance and unifying settings with the app. Appearance, Workspace, Switching and Permissions share native segmented navigation. Workspace owns the single-page width (80–90%, default 84%), screen selector and shared preset controls; width/screen controls are disabled while running and persist locally. Granted permissions remain here; only missing permissions appear on the manager. A chooser cancellation changes nothing. Selection and import each prevent duplicate requests; import has a visible loading state. Invalid images or write errors preserve the previously accepted background and show a local error. A missing/corrupt stored image falls back to frosted material with a visible explanation. The managed copy is bounded to 4096 pixels and a source file to 128 MB. Reset restores both transparency values to 35% and 24 pt wallpaper blur with frosted mode, retaining an image for reuse. Remove Wallpaper affects only the managed copy. Done/Escape closes settings; accepted changes already persist. Reduced Transparency/increased contrast overrides rendering only.

Horizontal input uses one router across local/global monitors with separate continuous and stepped gates. Default workspace scope includes the exact focused managed pane and tool surfaces. Other windows, settings, modal sheets and outside-screen input cannot open a global gesture. Recheck actual focus before continuous commit; cancellation or focus loss cannot apply a delayed layout. The global monitor observes only, so the original application's own content may also scroll; rail-only scope provides a content-scroll alternative. Non-precise mouse ticks scale by 12 and horizontal movement must exceed vertical by 1.25×. Stepped mode retains 250 ms idle reset, 450 ms cooldown and once-per-phase-gesture selection. Continuous mode retains a fractional position on phase end or its 160 ms unphased idle and allows further progress while its own preview is busy. Both discard momentum and unrelated busy/disabled input, stop at endpoints and never queue steps. Enabled/mode/distance/scope settings persist; transient gesture state does not.

Capture pixel dimensions come from `filter.contentRect × filter.pointPixelScale`, rounded up, while `NSImage` retains the window's original logical size in points. Edge previews preserve aspect ratio and use `min(1, availableHeight / imageHeight)` as their display scale, then crop horizontally toward the neighboring window's inward edge. A short image leaves background visible; it is not stretched or enlarged to fill the panel. The native-resolution and logical-size checks establish dimensions and metadata only. They do not establish legibility, correct visual correspondence or color; those require a separate visual check after the change.
