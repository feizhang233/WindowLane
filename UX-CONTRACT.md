# WindowLane interaction contract

Source: user's eight-part brief; v1 priorities are six windows, center/edges, click and shortcuts, order, expansion, restoration. `README.md` records public macOS API limits. No server, account, web form or remote storage.

A manager opens or resumes without modifying external windows. Start finishes optional captures, rechecks its operation token, then reads original geometry immediately before journaling and mutation. Version 0.2.1 prepares all managed windows unminimized at the same main frame and keeps them stacked. Normal selection serializes a direct native focus operation, preceded by a short nonanimated input shield that is released before actual focus handoff. Only after focus succeeds does the selected ID change and the UI leave its busy state. The previous window's snapshot refresh runs afterward in the background; preview failure retains the previous image or name card. Normal selection neither re-places the next window nor minimizes/hides the previous one. There is no 180 ms slide-completion dependency.

Expansion and its reversal place all managed windows at the new shared frame, then return focus to the active window. They must not change the saved original frame/minimized state. Stop invalidates tokens, cancels old operations and previews, waits for pending writes to unwind, then independently restores every original frame/minimization. New work remains blocked during restoration. Failures and journal write failures preserve recovery data for retry. App exit waits for Stop; repeated Stop cannot cancel restoration. A corrupt journal blocks Start until explicit acknowledgement. Closed windows are removed only after positive evidence; permission loss is not closure. Automated fixture runs have a separate per-run journal and never consume a user's unresolved records.

Retry does not depend on the narrower eligibility rules used to add new windows. Missing bundle/launch identity, unavailable or empty AX window lists, unreadable frames, ambiguous correspondence, and changing geometry keep the record pending. A confirmed different original process may be discarded; temporary identity/read failures may not. The same-session AX identity is preferred; restart lookup requires the saved WindowServer ID's owner and a unique complete geometry correspondence. A title match alone is never sufficient. After lookup, frame and minimized state must both restore successfully before the record is omitted from the next atomic journal. Failure to write that journal does not clear the in-memory queue.

Original frames can extend beyond a display edge. Temporary placement to permit growth may be used only as a step toward the unchanged saved frame. Final verification still checks the original target; silently accepting a smaller clamped frame is a failure, not completed recovery. The confirmed Safari bottom-edge clamp and the final recovery result are tracked separately in verification/TESTING.md.

Reordering uses stable IDs and keeps the active window selected. Drag and arrow actions are equivalent. Removal is reversible by adding the still-open window, and never closes an external document. The manager has a local bounded six-item lane and a scrolling discovered-window list; query clear is immediate. Native macOS control semantics, focus and shortcut labels are canonical. No modal approval for reversible layout changes. System permission controls remain owned by macOS.

Preview pixels are optional cached snapshots in memory. No live preview claim. A local recovery record under Application Support persists window identifiers, titles and original frames. Background settings persist in local preferences and the selected wallpaper has a managed PNG copy in Application Support; its source is never changed. No network storage or upload. Demonstration mode has a visible label and app-owned editable windows. Its test results cannot establish external-window integration.

Stacked windows remain real application windows. Occlusion is not closure and cannot clear their recovery records. Preview capture continues to target the exact desktop-independent window, including when it is covered by another managed window; a screen-rectangle capture cannot substitute for it. Transparent application content may show the window behind it. A user or target application that independently minimizes or changes a window can require corrective handling; the no-repeat-layout guarantee applies to the prepared normal-switch path. Start, expansion/reversal and restoration have separate geometry costs and latency evidence.

The standalone settings window shows the current mode, source filename and independently labeled application/workspace and settings-window transparency controls. Appearance, Switching and Permissions share native segmented navigation. Granted permissions remain here; only missing permissions appear on the manager. A chooser cancellation changes nothing. Selection and import each prevent duplicate requests; import has a visible loading state. Invalid images or write errors preserve the previously accepted background and show a local error. A missing/corrupt stored image falls back to frosted material with a visible explanation. The managed copy is bounded to 4096 pixels and a source file to 128 MB. Reset restores both transparency values to 35% and 24 pt wallpaper blur with frosted mode, retaining an image for reuse. Remove Wallpaper affects only the managed copy. Done/Escape closes settings; accepted changes already persist. Reduced Transparency/increased contrast overrides rendering only.

Horizontal input shares one gate across local/global monitors. Default workspace scope includes the exact active managed window and tool surfaces. Other windows, settings, modal sheets and outside-screen input cannot trigger a global switch. The global monitor observes only, so the original application's own content may also scroll; rail-only scope provides a content-scroll alternative. Non-precise mouse ticks scale by 12, horizontal movement must exceed vertical by 1.25×, idle reset is 250 ms and cooldown is 450 ms. Momentum and busy/disabled input are discarded; phase gestures trigger once and endpoint navigation does not wrap. Threshold/scope/enabled settings persist without gesture state.

Capture pixel dimensions come from `filter.contentRect × filter.pointPixelScale`, rounded up, while `NSImage` retains the window's original logical size in points. Edge previews preserve aspect ratio and use `min(1, availableHeight / imageHeight)` as their display scale, then crop horizontally toward the neighboring window's inward edge. A short image leaves background visible; it is not stretched or enlarged to fill the panel. The native-resolution and logical-size checks establish dimensions and metadata only. They do not establish legibility, correct visual correspondence or color; those require a separate visual check after the change.
